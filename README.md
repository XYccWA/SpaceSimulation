# SpaceSimulation 太空模拟

**简体中文** | [English](README_EN.md)

把主世界变成太空。一个基于 **NeoForge 1.21.1** 的模组：零重力星系的六自由度(6DOF)四元数飞行物理、位于世界中心的太阳、真实的牛顿轨道力学、数千万颗程序化生成的小行星，以及从太空矿石到航天合金的材料体系。

`Minecraft 1.21.1` · `NeoForge 21.1.234` · `v0.3.2-beta` · `GPL-3.0`

## 特性

### 太空化的主世界

主世界被重新定义为太空维度：没有天空光、没有重力、没有拖曳、没有大气压（维度类型 + Sable 维度物理数据包 `dimension_physics/overworld.json`：`base_gravity=[0,0,0]`、`base_pressure=0`、`universal_drag=0`）。黑色虚空天空、生物不再自然生成、流体静止不流动，玩家、生物、掉落物与箭矢全部自由悬浮。世界下限 −512、上限 1024。模组自身的引力不来自维度物理，而来自世界原点的太阳（见下）。

### 世界中心的太阳

- **种子派生的半径**：太阳球心位于世界原点 `(0,0,0)`，半径由主世界种子确定性派生，取值 5 万 ~ 10 万格（`SunRadius`）。服务端判定与客户端渲染共用同一公式，多人游戏中由网络包下发实际半径——「看到的太阳表面」就是「判定的太阳表面」。
- **高温区与表面处死**：球壳 `(R, 1.1R]` 为高温区，每 10 tick 结算一次伤害，越靠近表面越高（外缘 1 点 → 表面 20 点，按接近度平方增长）；距离 `d ≤ R` 触碰太阳表面立即处死（创造/旁观模式同样生效）。
- **出生点不再悬在虚空里**：旧的「距原点 500 万 ~ 1000 万格安全环」已删除。世界出生点会被纠正到初始轨道带，登录/重生落在太阳内时也有兜底；首次进入世界的玩家由轨道系统直接放进一条初始轨道（见下）。

### 轨道力学（玩家与生物）

- **真实引力场**：以世界原点的太阳为中心的平方反比引力，每 tick 数值积分（速度 Verlet），玩家与其它实体都受其驱动。引力参数 μ 默认 `6.25e6` 块³/tick²——100 万格处（内小行星带内缘）圆轨道速度 2.5 块/tick（50 m/s），500 万格处 1.12 块/tick，太阳表面 11.2 块/tick（224 m/s）。可在 `Orbital Mechanics` 配置中调整，设为 0 即关闭引力、回到旧的「无引力牛顿自由飞行」。
- **服务器权威 + 客户端预测对账**：服务端按客户端上报的输入掩码自行积分、忽略客户端的位置包，并把权威状态下发；客户端用同一套积分器本地预测，按输入序列号对账，偏差超过 `orbitalCorrectionBlocks`（默认 1 格）才回卷重放。两端积分器是同一份纯数值实现，且 μ 由服务端下发，保证多人与单机一致。
- **离线不 tick**：退出时保存当前密切轨道根数与登出 tick；下次登录按服务器 tick 解析传播（椭圆与双曲轨道都支持），离线期间轨道照常运行。
- **出生即在轨**：首次进入世界的玩家会在 `orbitalSpawnRadiusMin` ~ `orbitalSpawnRadiusMax`（默认 100 万 ~ 150 万格，即内小行星带）内分配到一条随机轨道，倾角与偏心率都被约束，使整条轨道留在与小行星带同一薄盘内（默认 |Y| ≤ 8000 格、e ≤ 0.15）；死亡重生默认也会重新分配一条轨道。
- **命令与 HUD**：`/orbit info` 查询 μ、半径、速度、六根数、周期与近/远心点，`/orbit circular <radius> [倾角]` 直接进入指定半径的圆轨道；`F3` 调试屏显示轨道半径、速度、根数与预测修正次数。
- 为了让服务器权威位置真正生效，中和了两个原版行为：连接 tick 会把服务端玩家回滚到 tick 前位置（权威位置在连接 tick 末尾重新写入），`LivingEntity.aiStep` 会清零小于 0.003 块/tick 的速度分量（两端因此各自维护权威速度，而不是读原版的 `deltaMovement`）。

### 四元数 6DOF 飞行

- 姿态由**四元数**而非欧拉角驱动，俯仰/偏航/滚转完全自由，没有 ±90° 钳制，也没有万向节死锁。
- `Q` 左滚转、`E` 右滚转（首次进入游戏自动重绑定原版按键：丢弃 `Q`→`DEL`、背包 `E`→`B`，并尊重玩家的自定义键位）。
- 加速度 24 m/s²，**速度上限 10 方块/tick（200 m/s）**；视角指数平滑，低帧率下物理方向与准星零滞后。推进（或刹车）产生的加速度会叠加在轨道力学的引力之上，因此正确做法是沿轨道方向加速，而不是与引力对抗。
- 碰撞箱随身体旋转：横飞时 1.8 格长的盒贴合身体，并通过 [Hitbox API](https://www.curseforge.com/minecraft/mc-mods/hitbox-api) 挂载**真旋转受击盒（OBB）**，`F3+B` 可查看。

### 加速度伤害

- **撞击冲击**：单 tick 速度骤降（撞击/急停）按减速量造成伤害。
- **持续高 G 过载**：瞬时 30 G / 持续 10 G（默认值，可配置）触发伤害，带去抖窗口。
- 检测在客户端本地完成、由服务端裁定，单机与多人行为一致；模组物理模式下禁用原版坠落伤害。
- **玩家免疫虚空伤害**：掉出世界下界不再是死路——玩家的垂直速度会被清零，停在触发线附近可自行飞回；其它生物/实体保持原版行为。

### 程序化小行星带

**零存储、确定性、数据包驱动**的小行星系统（只有被玩家改造过的小行星才会落盘）：

- 每颗小行星用**编号标识**，由 `SplitMix64` 从种子与编号派生**开普勒六根数**，按需 O(1) 计算——同一编号在任何会话、任何机器上都是同一条轨道，不占用任何存档空间。
- 运动遵循开普勒三定律（`T = 2π√(a³/μ)`、`E − e·sinE = M`）。默认 μ 直接跟随玩家的引力参数（`asteroidMuFollowPlayerOrbital`），因此小行星带与玩家处在**同一个速度尺度**上——内带内缘的圆轨道速度就是玩家在该半径的速度（2.5 块/tick，50 m/s），可以伴飞、减速、降落。
- **环带**由数据包定义（`asteroid_belt` / `asteroid_type` JSON）：内侧带 100 万 ~ 140 万格（碳质/硅质为主）、外侧带 160 万 ~ 200 万格（金属/稀有金属为主），高度区间 −8000 ~ 9000 格，各有密度与**加权类型**；共 **15 种类型 × 6 个变体结构 = 90 个结构 NBT**，整套系统约 3000 万颗（内带按平均间距换算约 1360 万，外带固定 1700 万）。
- **接近加载**：每 tick 以在线玩家为锚点，预加载索引按帧分摊重建（预载半径 5 万格）、强加载半径 2 千格实时检索，不阻塞主线程。
- **实体化**：进入默认 **1000 格**的小行星会被装配为 **Sable 子层级**——真正可以看见、降落与开采的方块结构（上限 **24 颗**、每 40 tick 一轮、离开后 200 tick 迟滞卸载、自转 3°/秒）。未安装 Sable 时退化为纯质点模型。
- **改造持久化**：你在小行星上挖掘、放置或炸掉方块后，这颗小行星会被标记为「已改动」；卸载时它经 Sable 原生子层级存储落盘并记录副本指针，再次靠近时优先按名字认领、按台账指针取回、必要时全量扫描兜底——取回的是**你改造后的方块**，而不是原始模板。没有改动过的小行星仍旧即时重建、不占存档空间。
- **方块交互延迟补偿**：服务器眼位天然落后客户端 1~3 tick，高速掠过小行星时会出现「准星明明对着方块却挖不动/放不下」。服务端现在改用客户端上报位置做几何判定、以权威位置钳制偏差上限，并在「当刻 / 前 1 tick / 前 2 tick」三个解析位姿中取最小距离，只放行不拒绝（`subLevelInteractionLagCompensation`，默认开启）。

### 材料体系

小行星矿石 → 矿砂 → 粉末 → 金属锭 → 航天合金锭的材料链（**工序尚未接入，见「已知问题」**）。

#### 矿石方块（26 种）

原有 20 种矿石，加上为补齐关键断链新增的 6 种：**辉砷钴矿**（钴）、**锂辉石**（锂）、**锆石**（锆）、**独居石**（稀土）、**晶质铀矿**（铀）、**钍石**（钍）。矿石方块统一掉落自身 1 个——不再直接掉矿砂，矿砂改由后续的破碎/选矿工序产出。

#### 矿砂与粉末（各 26 种）

- **金属矿砂**：辉铜矿、铁纹石、镍纹石、铬铁矿、钛铁矿、镁橄榄石、钨锰铁矿、铌铁矿、辉钼矿、钽铁矿、辉铼矿、辉砷钴矿、锂辉石、锆石、独居石、晶质铀矿、钍石
- **硅质矿砂**：橄榄石、辉石、斜长石、石英
- **碳质矿砂**：碳质、层状硅酸盐、碳酸盐、陨硫铁、磁铁矿
- 每种矿石对应一种矿砂与一种粉末（共 52 个物品），贴图与模型已全部补齐。

#### 金属锭（13 种）

铜、铁、镍、铬、钛、镁、钨、铌、钼、钽、铼、铂、铑

#### 合金锭（6 种）

铁镍合金、铬镍铁合金（Incoloy 890）、钨铼合金、镍铼合金、铂铑合金、GH4061 合金

### 光照与渲染

- **全亮光照**（默认开启）：所有光照查询直接返回最高亮度，原版光照引擎完全停止计算（无 BFS 传播、无逐方块更新），省下服务器 tick 与客户端帧的主要热点。
- **内建 Iris 光影包**：首次启动自动部署到 `shaderpacks/SpaceSimulation`，把世界中心的太阳渲染为**径向光源**并从它投射真实阴影（阴影有效范围内光线方向变化远小于一个像素，因此局部可精确视作平行光，方向取 `normalize(cameraPos)`）。仅在玩家尚未选择任何光影包时自动启用，不会覆盖已有选择；未安装 Iris 时该功能整体不生效。

### Sable / Create Aeronautics 集成

- **Plotyard 移入太阳**：Sable 的子层级方块存储（plotyard）网格被整体安置在太阳球体内部，使物理坐标保持在小量级（f32 精度由约 2 格提升到约 4 毫米）。
- **Rapier 浮点重基**：送往原生物理引擎的世界坐标按每场景原点平移，Java 侧的位姿/渲染/网络仍使用世界坐标 double，子层级物理在数百万格外依旧精确（`Sable Rapier Fix` 配置可整体关闭）。重基时的全局区块重传改为分帧进行（每物理帧 10 ms 预算），重基瞬间不再阻塞主线程。
- **子层级持久化**：改造过的小行星复用 Sable 原生的 holding 存储（`<世界>/sublevels/*.sls`），不额外自建存档格式。

## 命令

所有命令需要权限等级 2。

| 命令 | 作用 |
|---|---|
| `/asteroid meta` | 系统概况：环带、类型、总数、种子、引力参数 μ、数据包状态 |
| `/asteroid belts` | 环带列表：半径、倾角、离心率、档数、总量、类型权重 |
| `/asteroid info <index>` | 按编号查询：所属环带、类型/变体/结构、六根数、当前世界坐标与轨道速度 |
| `/asteroid near <radius>` | 查询玩家附近半径内的全部小行星（含耗时） |
| `/asteroid loader` | 预加载索引与强加载状态、耗时、进出事件 |
| `/asteroid spawn <index>` | 实体化一颗小行星（Sable 子层级），回显落块区与逻辑位姿 |
| `/asteroid tp <index>` | 实体化并传送到该小行星附近（径向偏 80 格）观察 |
| `/asteroid entity` | 当前实体化状态：数量、上限、每颗的 plot 与包围盒 |
| `/asteroid persist [index]` | 持久化台账：已改动的小行星与其存档副本指针 |
| `/asteroid persist <index> unload` | 强制卸载该颗并落盘（用于验证取回流程） |
| `/asteroid reload` | 手动重载小行星数据包并回显解析诊断 |
| `/orbit info` | 你的轨道状态：μ、半径、速度、六根数、周期、近/远心点 |
| `/orbit circular <radius> [倾角]` | 进入该半径的圆轨道（倾角 0° = 赤道面，90° = 极轨） |
| `/orbit mu` | 当前引力参数 |

## 配置

配置文件为 `config/space_simulation-startup.toml`，以下为常用项：

| 配置 | 默认 | 说明 |
|---|---|---|
| `fullBrightness` | `true` | 全亮光照；关闭即恢复原版光照 |
| `orbitalMechanicsEnabled` | `true` | 玩家与实体的真实轨道力学（关闭即回到无引力自由飞行） |
| `orbitalMu` | `6.25e6` | 太阳的引力参数 μ（块³/tick²）；圆轨道速度 `√(μ/r)`，设为 0 关闭引力 |
| `orbitalCorrectionBlocks` | `1.0` | 客户端预测与服务器权威状态的偏差阈值，超过即回卷重放 |
| `orbitalSpawnEnabled` / `orbitalSpawnOnRespawn` | `true` | 首次进入世界 / 死亡重生时分配初始轨道 |
| `orbitalSpawnRadiusMin` ~ `orbitalSpawnRadiusMax` | `1.0e6` ~ `1.5e6` | 初始轨道半径范围（格） |
| `orbitalSpawnMaxAbsY` / `orbitalSpawnMaxEccentricity` | `8000` / `0.15` | 初始轨道最大 \|Y\| 与最大偏心率 |
| `asteroidSeed` | 固定值 | 小行星宇宙种子，改变它即确定性重建全部轨道 |
| `asteroidMuFollowPlayerOrbital` | `true` | 小行星轨道跟随玩家的 μ（否则用独立的 `asteroidInnerOrbitPeriodTicks`） |
| `asteroidInnerOrbitPeriodTicks` | 62830000 | 仅在上一项为 `false` 时生效：最内带内缘周期，据此反推 μ |
| `asteroidEntityifyEnabled` | `true` | 是否把靠近的小行星实体化为 Sable 子层级 |
| `asteroidEntityifyRadius` / `MaxLoaded` / `LoadIntervalTicks` | 1000 / 24 / 40 | 实体化半径、同时存在的上限、装载节流 |
| `asteroidSpinDegPerSecond` | `3.0` | 小行星自转速度，0 关闭 |
| `subLevelInteractionLagCompensation` / `subLevelInteractionLagTicks` | `true` / `4` | 子层级方块交互延迟补偿，以及允许客户端位置超前权威位置的 tick 当量（0 关闭补偿） |
| `rapierRebaseEnabled` | `true` | Rapier 浮点重基（远距离精度修复） |
| `builtInShaderPack` / `autoEnableShaderPack` | `true` | 部署/自动启用内建 Iris 光影包 |
| `sustainedGThreshold` / `highGravityAccelerationThreshold` | 98.1 / 294.3 | 持续过载与瞬时过载伤害阈值（m/s²） |
| `perfStatsEnabled` | `true` | 每 60 秒输出一行服务器性能统计（tick 耗时、TPS、实体/区块/小行星数、堆内存） |

## 数据包

小行星环带与类型完全由数据包定义，可直接在存档或模组包中覆盖：

```
data/<namespace>/asteroid_belt/<name>.json      环带：半径、高度、密度、离心率、类型权重
data/<namespace>/asteroid_type/<name>.json      类型：显示名、变体结构列表
data/<namespace>/structure/<name>.nbt           小行星结构
```

修改后执行 `/asteroid reload`（或 `/reload`）立即生效。

## 构建

需要 JDK 21。

```bash
./gradlew build                                      # 产出 build/libs/space_simulation-<version>.jar
./gradlew runClient                                  # 开发环境启动客户端
./gradlew runClient -PquickPlaySingleplayer=<世界名>   # 直接载入单机存档测试
```

推送 `v*` 标签会触发 GitHub Actions 构建、发布 GitHub Release，并（在配置了 `CURSEFORGE_TOKEN` Secret 时）自动上传 CurseForge。

## 已知问题

- **生存材料链未完成**：矿石的世界生成、破碎/选矿工序与冶炼配方尚未接入——矿石方块目前只掉落自身，矿砂/粉末/锭只能在创造模式获取（最高优先待办）。
- **轨道力学的调参仍在进行**：μ、初始轨道带与修正阈值都可在配置中调整，速度尺度与操作手感可能还会变化。
- **科技树尚未实现**：完整设计（残骸回收型科技树、能源、真燃料推进、载具武器、小行星三态）见 `docs/tech-tree-design.md`；当前版本只落地了矿物层面的准备。
