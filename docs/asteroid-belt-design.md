# SpaceSimulation 小行星带系统设计

- 状态:设计稿 v0.1(未实现,无代码)
- 适用:NeoForge 1.21.1 / Java 21,主世界改造(非新维度)
- 关联对话:https://chat.deepseek.com/share/216ge5s20lfnr6u5aw(思路来源,已全文归档于 `.analysis/share_conversation.txt`)
- 关联系统:太阳渲染(原点半径 150000)、太阳警戒线(solarKillRadius)、统一出生点(500万~1000万格圆环)、6DOF 飞行、sable 子层级

---

## 1. 背景与目标

把原版主世界改造成一个**恒星系**:无星球,只有一条**有轨道运动的小行星带**。

用户明确需求:

1. 带区位于**距原点 1000 万 ~ 2000 万米**的环形空间(XZ 平面圆环,Y 方向薄层)。
2. 小行星**沿轨道运动**(开普勒轨道,不是静态摆件)。
3. **不稀疏、不吃性能**:视野内密度适中;服务器/内存开销可控。
4. **质点化**:每颗小行星在未加载时只是一个"质点"(纯数据,不占方块、不参与碰撞、不逐 tick 更新);只有当质点接近玩家时才**实体化**(生成真实方块)。
5. **不用静态空间扇区划分**:小行星动态运行会跨扇区,静态扇区索引会过时。
6. **世界生成时不需要预生成全部轨道参数**:只保存"规则 + 种子",小行星按需涌现。
7. 直接改造主世界(现有主世界已是全空气虚空 + 固定 biome asteroid_belt,见 §2)。

## 3. 总体架构

三层结构 + 一个贯穿的时间模型:

```
┌────────────────────────────────────────────────────────────────┐
│  时间模型:position = f(轨道根数, 游戏 tick)  —— 纯函数,无状态      │
└───────────────┬────────────────────────────────────────────────┘
                │
┌───────────────▼────────────────────────────────────────────────┐
│  种群注册表(核心,服务端+客户端共用同一确定性算法)                    │
│  · 轨道参数空间细网格(隐式,hash 驱动,零存储)                      │
│  · 每单元接受概率 p(a,e,i)(密度标定)                              │
│  · 查询:玩家位置+时间 → 几何逆推 → O(10⁴~10⁵) 候选单元 → 精确位置    │
└───────┬───────────────────────────────┬────────────────────────┘
        │ 附近(≤ 加载范围)                │ 远处(加载范围之外)
┌───────▼──────────────────┐   ┌─────────▼────────────────────────┐
│ 实体化层(服务端权威)        │   │ 远层渲染(客户端)                   │
│ ChunkEvent.Load → 盖章     │   │ 尘埃带 shader(密度场沿视线积分)     │
│ 活动小行星注册表(冻结位置)   │   │ 点精灵(分层采样 + 相机相对坐标)      │
│ ChunkEvent.Save → 剥离     │   │ 缓存 1~2s + 视锥裁剪               │
│ 方块随 chunk 包发给客户端    │   │ 纯装饰,不影响玩法                  │
└───────────────────────────┘   └──────────────────────────────────┘
```

- **服务端权威**:实体化(盖章方块)只发生在服务端,经正常 chunk 包同步到客户端——**无需任何额外网络同步**。
- **客户端独立远层**:客户端用同一确定性算法 + 世界种子渲染远处小行星,纯装饰。
- **无持久化**:小行星不存在于存档中(位置是时间函数);磁盘上只有玩家编辑过的方块。

## 4. 小行星种群模型(质点)

每颗小行星 = 一组轨道根数 + 一个形状种子,未加载时零占用:

| 字段 | 含义 | 取值范围(默认) |
|---|---|---|
| a | 半长轴 | [1e7, 2e7] m,径向密度峰值 ~1.5e7 |
| e | 偏心率 | 量化值 {0, 0.03, 0.06, 0.09, 0.12, 0.15}(离散化见 §5.2) |
| i | 轨道倾角 | [0°, 10°],垂直剖面由 i 分布塑造 |
| Ω | 升交点经度 | [0°, 360°) 均匀 |
| ω | 近心点幅角 | [0°, 360°) 均匀 |
| M₀ | t₀ 时刻平近点角 | [0°, 360°) 均匀 |
| seed | 形状/矿物种子 | hash(单元坐标, 世界种子) |
| 类型 | 岩石/金属/冰/富矿… | 按权重,决定材质调色板(§10) |
| 尺寸 | 等效直径 | 幂律分布 α ≈ -2.5,区间 [3, 500] m;实体化上限另定(§13) |

**位置是算出来的,不是存的**:`M(t) = M₀ + n·(t − t₀)`,平均角速度 `n = 2π/T`,`T = T_inner·(a/a_inner)^1.5`(开普勒第三定律)。解 `M = E − e·sinE`(牛顿迭代,e 小收敛快)得偏近点角 E,再转真近点角 ν 与轨道半径 r,经 Rz(Ω)·Rx(i) 旋转变换到世界坐标。全程 double。

**轨道周期(默认)**:内缘(a=1e7)T = 30"轨道日",外缘 ≈ 85 轨道日;1 轨道日 = 86400 tick(可配)= 72 真实分钟,故内缘周期 ≈ 36 真实小时,线速度 ≈ 24 m/s(1.2 块/tick)。见 §8。

## 5. 核心算法:确定性生成与附近查询

### 5.1 被否决的方案(含原因)

| 方案 | 否决原因 |
|---|---|
| 静态空间扇区划分 | 小行星沿轨道运动,会跨扇区;列表过时需频繁重建(用户已否决) |
| 时空网格(空间 × 时间量子) | 小行星身份按量子跳变,切换瞬间消失/出现,淡入淡出也掩盖不了身份断裂 |
| 预生成全部轨道参数目录 | 全带约 10¹² 颗,存储/初始化不可行 |
| 逐 tick 物理模拟 | 数量级不可行 |
| 实体化为"移动方块结构" | MC 中移动方块结构实现成本极高,不推荐(对话结论一致) |

### 5.2 推荐方案:轨道参数空间细网格 + 接受采样(对对话方案的修正)

对话中提出的"轨道参数空间索引"方向正确,但其粗粒度网格版本有一个**正确性缺陷**:它用"包含目标 M₀ 的 bin"定位小行星,但粗 bin(如 M₀ 每 15°)内的小行星 M₀ 是随机分布的,并不等于目标值——检查到的单元里的小行星实际位置可能偏离目标 **r·ΔM ≈ 数百万格**。修正要点:

1. **角向 bin 必须足够细**:λ 与 M₀ 的 bin 宽度 Δ 需满足 `r·Δ ≲ R_load`(R_load ≈ 256 m,r ≈ 1.5e7 → Δ ≈ 0.001°,即 36 万 bin)。
2. **每单元至多一颗小行星,以接受概率存在**:单元 (a_bin, e_val, i_bin, λ_bin, M₀_bin) 是否有一颗小行星 = `hash(单元, 世界种子) < p(a,e,i)`(确定性)。密度由 p 标定(见 §5.4)。
3. **e 离散化为少量取值**(6 个),消除 e 维的包络膨胀;i 保持连续(细 bin 枚举,见下)。

网格全部**隐式**(由坐标 hash 生成),无任何存储。单元总数约 2e4(a) × 6(e) × 1e4(i) × 3.6e5(λ) × 3.6e5(M₀) ≈ 10²²,但查询只触碰其中 O(10⁴~10⁵) 个。

### 5.3 查询算法:几何逆推

输入:玩家位置 P = (x, y, z)(double)、当前游戏时间 t、查询半径 R。输出:单元内小行星精确位置,筛出 |pos − P| < R 的质点。

1. **半长轴范围**:小行星径向距离 ∈ [a(1−e), a(1+e)],需与 [|P|−R, |P|+R] 相交 → 由 |P|±R 与 e_max 反解 a 区间,通常只覆盖 1~3 个 a-bin。
2. **倾角枚举**:轨道垂直范围 |y| ≤ r·sin i,故 i ≥ arcsin(max(0, |y|−R)/r);对满足条件的 i-bin(约 0~1e4 个)逐个处理。
3. **每 (a,e,i) 组合的精确解**(闭式/数值):
   - 由 r = a(1−e²)/(1+e·cos ν) 解真近点角 ν(0~2 个解);
   - 由 y_world = r·sin ψ·sin i 解纬度幅角 ψ(0~2 个解);
   - 由方位角方程解 Ω(0~2 个解);
   - 得 ω = ψ − ν、M₀ = M(ν) − n·t——**精确落到唯一一个细 bin**;
4. **接受测试**:hash(单元) < p(a,e,i) 则存在小行星 → 计算其精确位置(用其单元内随机化的真实根数)→ 距离过滤 → 加入结果。

**复杂度**:≈ 3(a) × 6(e) × i_bins × O(1) 次 hash 测试。|y| 小时 i_bins ≈ 1e4 → 单次查询 ≈ 5 万~50 万次 hash ≈ **1~5 ms**。位置缓存(见 §5.5)后实际开销可忽略。

### 5.4 密度标定

- 目标空间密度 ρ(r, y)(asteroid/m³):径向高斯(峰值 ~1.5e7,σ ≈ 数百公里量级)+ 垂直高斯(σ ≈ 250 m)。
- 接受概率按类标定:`p(a,e,i) ∝ ρ_target(a, i)`,具体系数由"单元包络体积 × 相交单元数"的理论公式为初值,**以蒙特卡洛密度探针实测标定**(开发期工具,见 §12)。标定正确性判据:随机采样 N 个 (P,t),统计半径 R 球内小行星数,均值 ≈ ρ·(4/3)πR³。
- 大小分布由单元内种子抽样独立于轨道参数(幂律 α ≈ −2.5,直径 [3, 500] m)。

### 5.5 性能与一致性要点

- **查询缓存**:玩家 1~2 s 内位置变化 < 50 m(小行星最坏 24 m/s),缓存查询结果;玩家移动超阈值或时间超窗才重查。
- **时间一致性**:位置只依赖 tick,服务端重启、多玩家、客户端各自计算,结果天然一致。
- **同一颗小行星的识别**:身份 = 单元坐标(静态),任何玩家/任何时刻查询同一单元得到同一小行星 ✓。
- **远层抽样**:远处渲染不需要完整枚举,对 (a,e,i,λ,M₀) 做**分层抽样**(按固定 stride 跳查),抽到的就是真实小行星(与近层同网格)→ 玩家靠近时近层查询能找到同一颗,无缝衔接。

## 6. 实体化层(方块,服务端权威)

### 6.1 机制:盖章 at Load / 剥离 at Save

**磁盘上永远只有空气 + 玩家编辑**。小行星方块是"运行时视图":

- **盖章**(`ChunkEvent.Load`,服务端,仅 ServerLevel):区块从磁盘加载或新生成后,查询该区块附近的小行星(查询中心 = 区块中心,R = 区块尺寸 + 小行星半径),把每颗的方块切片写入区块。修改经正常 chunk 包发给客户端,零额外同步。
- **剥离**(`ChunkEvent.Save`,服务端):序列化前,把"仍处于原始盖章状态"的小行星方块恢复为空气。玩家改动过的方块(与盖章时 SDF 结果不一致)保留,由原版存档持久化。
- **自愈**:服务端崩溃导致带方块落盘时,下次盖章先按活动注册表剥离旧盖章再盖新章(幂等,见 §6.2)。

为什么是"加载时"而不是"生成时":磁盘上已存在的 chunk 不会重新走生成流程,只有加载时盖章才能覆盖"新生成"与"重新加载"两种路径,保证行为一致。

### 6.2 活动小行星注册表(冻结位置)

- 服务端维护 `asteroidId → 冻结位置(盖章时刻的轨道位置)` + 引用计数。
- 同一颗小行星跨多个 chunk:所有 chunk 盖章时**引用注册表中的同一冻结位置**,避免相邻 chunk 因加载时刻不同而把同一颗小行星盖在两个位置(接缝问题)。
- 引用计数归零(所有覆盖 chunk 卸载)→ 移除注册表项。玩家站在小行星上时其所在 chunk 必然保持加载,不会误卸载。
- 冻结语义 = 对话方案"轨道冻结":加载期间小行星静止,玩家可正常站立/挖掘;卸载后按轨道继续运动,下次加载出现在新位置。**"玩家被甩出去"问题在块级方案下天然不存在**。

### 6.3 块级生成(SDF,chunk 局部)

不预生成整颗小行星的形状,而是**逐 chunk 按 SDF 判定**:

- 小行星形状 = 以 seed 驱动的 3D 噪声球(半径 r,带表面起伏),即距离场 `sdf(局部坐标) < 0` 为实心;
- 盖章 chunk C 时,对 C 内落在小行星包围球中的每个方块坐标,用**局部坐标**(减去冻结位置,数值 < 数百米)求 SDF——局部坐标精度无忧,且与 chunk 无关,天然跨 chunk 一致;
- 材质按类型调色板 + 深度(表面壳层/内核/矿脉)选择(§10);
- 单次盖章成本:每颗 ~几十~几千方块,每区块 0~3 颗,~ms 级。

### 6.4 玩家修改的持久化(锚定世界模型)

- 玩家挖掉/替换/新增的方块**留在原地**(由原版 chunk 存档持久化),不跟随小行星移动——小行星移走后留下"漂浮残骸"。
- 收益:无需差异数据注册表、无需处理方块实体迁移、存档格式零改动;"带区是无限资源"经济(挖空一颗,新位置不断有新的)。
- 代价:半挖的矿不会保持"半挖"状态跟随移动(v2 可做随动差异,见 §13)。
- 盖章位置记录于区块级 `pos → asteroidId` 表(内存,加载时重建),供剥离判断"是否原始状态"。

### 6.5 光照与事件

- 盖章用 `LevelChunk.setBlockState(pos, state, false)`(无事件/无更新)批量写入,随后**对受影响 section 触发一次光照重算**(skylight 世界,空气 chunk 光照 15,盖章后需重算以正确照亮表面)。
- 避免盖章时触发 LevelEvent/方块事件,防止与方块实体、监听器交互。

### 6.6 性能预算

| 项 | 量级 |
|---|---|
| 盖章单 chunk | 1~5 ms(查询 ~1 ms + SDF 写入) |
| 区块加载速率(200 m/s 飞行) | ~12.5 chunk/s → ~60 ms/s,可忽略 |
| 同时加载的小行星 | 视野 192 m 内约 20~60 颗,总方块 ~10⁴,远低于区块方块预算 |
| 剥离 at Save | 同盖章量级,保存路径异步 |
| 内存 | 每 chunk 盖章表 + 活动注册表,KB 级 |

## 7. 远层渲染(客户端,纯装饰)

加载范围(视距 ~192 m)之外到几十 km 的视觉,分两层:

1. **尘埃带 shader(必做,效果主力)**:全屏后处理,复用太阳渲染的"视线重建"管线(`gl_FragCoord` → 逆投影 → 视线方向,相机相对坐标)。逐像素对带区密度场 ρ(r, y) 沿视线积分(薄环近似:取视线最近点处的密度 × 弦长),输出带区辉光。视觉上:沿环切线方向看是一条亮带,径向看是薄环;叠加在星空背景上,给出"身处小行星带"的整体感。
   - 注意精度:密度场采样用世界坐标 → 需要 double 相机位置传入(或把密度场定义在相机相对坐标),不能沿用太阳 shader 的 float 世界坐标采样(1.5e7 处 float ULP = 1 块,噪声采样会量化为 1 块步进——对太阳纹理不可见,对带区同样不可见,可接受;点精灵位置必须 double 计算)。
2. **点精灵(分层抽样)**:用 §5.5 的分层抽样从注册表取远处真实小行星(限数,如 ≤512 个,LOD 按距离):直径 ≥ 数米、距离 < 数十 km 的小行星渲染为公告板光点(大小 ∝ 直径/距离,颜色 ∝ 类型)。玩家靠近时,近层盖章会命中同一颗(同网格),衔接一致。
3. **缓存与更新**:点精灵列表 1~2 s 重建一次;位置随 tick 重算(24 m/s 下 2 s 内移动 ~50 m,视觉平滑);进出视锥用淡入淡出。

客户端输入:世界种子(level 数据自带)+ 带区参数(数据包 JSON,见 §10 集成)→ 本地确定性计算,无需网络同步。

## 8. 时间模型

- 唯一时间源:**服务端绝对游戏 tick**(`ServerLevel.getGameTime()`),跨重启持久、多玩家一致、客户端可读(渲染用)。
- 轨道时间尺度与 MC 日解耦:1 轨道日 = `beltOrbitDayTicks`(默认 86400 tick = 72 真实分钟)。
- 默认参数:内缘周期 30 轨道日(≈36 真实小时)↔ 线速度 ≈24 m/s;外缘 ≈85 轨道日 ↔ ≈17 m/s。
- 意义:加载期间小行星静止(冻结);卸载/重载之间的漂移速度 = 24 m/s,玩家离开数分钟再回来,带区已明显"走过",轨道运动可感知;同时单次会话内几乎不会看到同颗小行星大幅移动,体验稳定。

## 11. 边界情况与风险

1. **精度**:1.5e7 处 float ULP = 1 块——轨道/盖章/SDF 全 double;渲染顶点相机相对坐标(float 相对量 < 数十 km,安全);point sprite 位置 CPU 侧 double 计算、GPU 侧相对坐标传入。复用既有教训(绿盒抖动、太阳 shader)。
2. **跨 chunk 接缝**:同一小行星必须盖在注册表冻结位置(§6.2),禁止各 chunk 独立计算当前位置。
3. **崩溃落盘**:盖章前先剥离旧盖章(幂等自愈,§6.1)。
4. **方块实体**:v1 规则 = 小行星本体只含普通方块;玩家放在小行星上的容器/设备按"锚定世界"处理(留在原地,随剥离语义不迁移)。带方块实体的小行星方块(未来)需差异注册表,列入 v2。
5. **sable plot 边界**:带外缘 20,000,000 与 sable 默认 plot 起点 20,480,000 相距 48 万格;若未来把带外缘调大或改 plot origin,需重新核对重叠。
6. **结构/生物**:全空气世界无地形,原版结构落点条件不满足(需验证 ModStructurePlacements 无冲突);`disable_mob_generation: false` 下,夜间小行星表面(实心方块)可能刷敌对生物——v1 接受或经 biome 数据关闭。
7. **存档兼容**:现有世界启用带区无需迁移(纯运行时);玩家在带内放置的方块正常存档。
8. **多人**:盖章/剥离/注册表全服务端权威;两玩家靠近同一小行星共享同一冻结位置;区块卸载须等所有玩家离开(区块 ticket 机制天然保证)。
9. **远层与近层观感一致**:远层抽样必须来自同一网格,避免"远处看到、近处没有"的穿帮。

## 12. 测试与验收

按项目约定:默认测试 = 进世界并退出无异常(~1 分钟);专用冒烟测试用系统属性门控;自动退出直接 `mc.stop()`。

- **P0 单元测试(纯 Java,无游戏)**:查询算法——确定性(同 (P,t) 两次查询结果一致)、密度探针(随机点球内计数 ≈ ρ·V,±20%)、复杂度(单次查询 < 10 ms)。
- **P1 游戏内冒烟 `-Dspacesim.belttest=true`**:进世界 → 传送到带区(如 (1.5e7, 0, 0) 附近)→ 校验:周围 chunk 出现盖章方块;同一冻结位置跨 chunk 无接缝;保存后磁盘 region 中该区域为空气(日志断言);卸载重载后小行星位置随 tick 变化(日志断言)→ 截图 → 自动退出。验收标准 = 进世界 + 无异常 + 无 ERROR + 无残留进程。
- **P2 远层视觉**:带内截图(切线方向看尘埃带、径向看薄环、近处点精灵)→ 人工确认(按约定不再跑 kimi 视觉,除非用户要求)。
- **P3 玩法定量**:矿物分布抽样统计;玩家挖矿/放置 → 存档 → 重进 → 残骸保持、小行星位置变化。

## 14. 待决策问题(请用户确认)

1. **快旅行方式**(从出生环 5~10M 到带区 10~20M,200 m/s 需 7~14 小时):巡航加速模式(速度上限提到 ~2000 m/s)/ 跃迁点(出生环 + 带区各一传送门)/ 仅调试命令。**建议:巡航加速**,与现有飞行系统同构,沉浸感最好。
2. **轨道时间尺度**:默认"1 轨道日 = 72 真实分钟、内缘 30 轨道日 ≈ 36 小时"是否合适?还是希望更快(数分钟可见移动)或更慢(真实天数)?
3. **玩家修改模型**:v1 锚定世界(挖空/建造留原地,带区无限资源)是否接受?v2 随动差异(半挖的小行星保持半挖状态跟随移动)是否列入远期?
4. **实体化尺寸上限**:大天体(直径 > 128 m)也实体化(占用大范围 chunk)还是仅远层渲染?建议 v1 上限 128 m,更大的仅远层。
5. **密度确认**:平均间距 80~120 m(视野内 20~60 颗、最近 ~50 m)是否符合"不稀疏"预期?过密可调。
6. **方块实体策略**:小行星上放置容器/设备是否允许(允许则需 v2 差异注册表或"残骸"规则)。
7. **带区参数载体**:数据包 JSON(客户端一致、免同步)vs 纯配置(仅服务端,远层观感可能漂移)。建议数据包 JSON。
8. **带区与太阳的视觉协调**:从带内看太阳是否要做距离衰减/尺寸调整(太阳 shader 现为无限反比光晕)。
